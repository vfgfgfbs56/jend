# M7.9 — Zero-install Model Slots

A user selecting a model in Jend Store must not imply an eager multi-gigabyte
download.

Jend already limits an account to three model slots. M7.9 makes that selection
concept explicit: changing a slot changes entitlement/selection state first.
Weight residency is a separate device cache concern.

## User experience

```text
Store -> Select model -> immediately appears in chat
                         |
                         +-- provider adapter: no weights
                         +-- virtual model: small bootstrap + lazy pages
                         +-- full-local: optional explicit large download
```

For a virtual model, M7.9 demonstrates a 32 MiB bootstrap and a 64 MiB cache
budget. Those values prove that *selection footprint* can be megabyte-scale.
They are not a claim that a 1T model with a 16 GB active working set can perform
full-speed offline inference from only 64 MiB.

## Working-set honesty

`ExecutionReadiness` explicitly distinguishes:

- `ProviderReady`
- `LocalWorkingSetPossible`
- `StreamedOnDemand`
- `NeedsMoreLocalData`

If the cache is smaller than the declared active working set:

- online devices may page signed weights on demand, with latency dependent on
  bandwidth/page locality;
- offline devices are marked `NeedsMoreLocalData` rather than pretending the
  model is ready.

This prevents the Store UI from marketing "64 MB installed" as "64 MB is enough
to execute the whole model locally."

## Cache lifecycle

When a user replaces one of the three selected models, the selection epoch
increments immediately. If `evict_unselected_cache` is enabled, old weight
pages may be reclaimed in the background. Shared content-addressed pages used by
another selected model remain reusable in the future Model Fabric.

## Why this helps trillion-scale work

The long-term target is not a huge model file per user. It is a small selected
model identity plus an adaptive working-set cache. M8 WeightVM will decide page
residency across SSD/RAM/GPU/NPU and may fetch pages from licensed origins/CDN
or future distributed sources.

There is still a physical lower bound: high-speed local inference needs its
active computation data close to the accelerator. Models whose active path is
many gigabytes cannot achieve server-like token rates from a tens-of-megabytes
cache without either repeated network transfer, a different model architecture,
or computation occurring somewhere else.
