# M8.5.13 — Bridge real Xet decode to independently release-signed WeightPage admission

## Why this milestone

The Mac M8.5.12 opt-in live HF/Xet test produced:

```text
Jend live Xet scheduled signed HTTP 206: PASS
Jend live Xet physical-to-logical reconstruction: PASS
Jend live Xet unverified bytes kept outside WeightVM: PASS
Jend live Xet strict multipart network execution: NOT_EXERCISED (source returned singleton entries)
Jend live Xet separate signed multi-entry fetches: NOT_EXERCISED (one entry)
Jend live Xet fetch summary: single_jobs=1, multipart_jobs=0, physical_bytes=1090726, decoded_ranges=1, logical_bytes=1048576
```

That demonstrates a real one-megabyte logical slice, NOT a Jend-authorized
WeightPage or a validated full model.

M8.5.6 already implemented the independent Ed25519 signed-virtual-map and
signed-source-map trust gate, `VerifiedSourceReadRequest` opaque proof and
`DurableWeightPageStore::put_verified_source_page` length+SHA-256 checking
before staging. M8.5.13 **reuses** that logic; it does not reimplement Ed25519,
mint a page hash from fetched bytes or reinterpret a Hugging Face/Xet token
as a Jend model-release signature.

## New source-to-page bridge

`client/jend-cli/src/verified_xet_page_bridge.rs` accepts:

- An independently pinned/trusted `ModelReleasePublicKey` from the
  application's release trust policy. The caller must NOT derive the trusted
  key from the untrusted network response, SourceMap or URL.
- Release-signed source and virtual maps which must agree on the same model,
  release sequence and complete logical page set.
- A signed-map page/source identity and the expected immutable HF
  `repo_id` + full commit SHA + file path + source byte offset.
- Strictly validated physical Xorb ranges and reconstruction metadata,
  with bounded physical and decoded byte limits.

Only the existing release-key verifier can mint `VerifiedSourceReadRequest`.
No staged object is created on failure of the signature, source identity,
source offset, Xorb decoder, logical reconstruction or exact signed page
hash/length. The durable store rechecks staging and atomically publishes the
content-addressed object. WeightVM then independently rechecks SHA-256 and
length on page fault before residency.

**No new network capability is added to `jend-model-store` or WeightVM.**

## Offline Mac test, no token

```bash
bash scripts/dev-xet-signed-page-admission-smoke.sh
```

Expected:

```text
Jend Xet release-signed source+virtual map admission: PASS
Jend Xet immutable HF source and offset binding: PASS
Jend Xet modified digest/length rejected before staging: PASS
Jend Xet untrusted signing key and maps rejected: PASS
Jend Xet durable signed WeightPage and WeightVM lease: PASS
Jend Xet page admission uses synthetic offline fixture only: PASS
```

The fixture uses two different Xet signed range URLs and tiny untrusted Xorb
chunks encoding `abcdef`. It independently constructs a test-only release
key, signs expected SourceMap + VirtualMap, checks corruption/short reads,
wrong source offsets/origins, a different release key and map tampering, and
then proves exact-match durable publication and WeightVM lease. It does not
simulate a real, trusted production signing authority.

## Remaining work / no false trust claim

The Mac live GPT-2 probe DID NOT provide an independently Jend-signed release
manifest, source map or virtual map for the actual GPT-2 bytes. Do not attempt
to use the test-only release signing key or hash the freshly downloaded
network data and then "sign" it locally; that would self-authorize the
untrusted source and defeat the intended trust boundary.

To publish **real** Xet-derived pages in WeightVM, a trusted publisher/release
pipeline must produce release-specific, independently signed SourceMap and
VirtualModelMap artifacts tied to the immutable HF source and exact page
digests. A secure trust-root distribution and user-facing artifact loader,
real network source-worker integration with signed read coordinates and
streamed multi-page delivery remain separate milestones. No live
release-signed page was admitted in this milestone. M8.5/M8.6 remain open.
