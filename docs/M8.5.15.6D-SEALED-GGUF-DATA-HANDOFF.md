# M8.5.15.6d — sealed GGUF DATA handoff

**No production inference.** The fixture uses a synthetic 24-byte GGUF header
plus inert test bytes. It is not a valid complete model, GGUF parser or llama
engine. Both model and executable signing keys are ephemeral test authorities.

The M8.5.15.5 lease pins an opened inode but cannot prevent a writer changing
that inode. 6d consumes that same lease, copies bounded candidate bytes into a
private memfd, seals it, then verifies the final immutable object before native
handoff. There is no model pathname, arbitrary FD, private prompt or key grant.

1. Trusted Rust supplies independently enrolled model key, signed manifest,
   separately accepted manifest ID and a 24-byte–4-MiB policy ceiling. Wrong
   key/signature/identity/budget fails before native launch.
2. The model-store exposes a bounded candidate-copy method on its opaque lease,
   retaining the same inode and rechecking its signed identity first. This
   method alone grants no native authority: a writer can race the copying.
3. Create memfd with MFD_NOEXEC_SEAL, copy in 64-KiB buffers, set mode 0400 and
   require WRITE/GROW/SHRINK/SEAL/EXEC seals. Failed seal inspection refuses.
4. The trusted parent reopens only its own still-held anonymous inode via
   `/proc/self/fd/N` to obtain O_RDONLY, verifies dev/inode, no execute mode,
   access mode and seals, then checks final header, every signed chunk, exact
   length and whole SHA256 through the shared Rust reader verifier. The parent
   requires procfs; an unavailable/denied downgrade fails closed. No procfs
   access is granted to native code. Writable staging handle is dropped.
5. Extend the trusted launcher with one opaque approved model capability.
   Duplicate source handles above remap slots before fork to avoid FD 3/4
   aliasing. Kernel exec FD 3 remains CLOEXEC; O_RDONLY model FD 4 survives.
   Close everything >= 5, set NOFILE=5 (actual remaining 0/1/2/4), retain all
   existing Landlock/network/process/memory/CPU/timeout controls before exec.
6. Seccomp adds pread only on FD 4 and read-only fcntl getters. Default deny
   still forbids new handles, dup, paths, network, processes and re-exec.
   mmap/mprotect with PROT_EXEC is denied, including anonymous mappings and
   high-half protection/FD arguments. pkey_mprotect remains default denied.
   MFD_NOEXEC_SEAL protects inode execute mode; mapping execution is separately
   denied by seccomp. No JIT, dynamic loader or GPU driver profile is granted.
   Require explicit non-executable PT_GNU_STACK in the signed ELF. Reset inherited
   personality to PER_LINUX before exec; only its read-only query is allowed.
   This prevents READ_IMPLIES_EXEC from silently turning PROT_READ into execution.
   Constructor checks personality zero and denial of re-enabling this flag.

The new hostile constructor retains the original file/network/process/parent
state attack checks. Before main it reads the exact synthetic bytes by pread
and shared read-only mmap, checks seals/O_RDONLY/size/NX, and requires actual
kernel rejection of write, truncate, chmod, shared writable mapping, PROT_EXEC,
mprotect escalation and execveat on the model. All other inherited FDs are
closed. Source inode mutation/path replacement cannot alter the prepared data.

The portable reader regression verifies appended/truncated data and mismatched
signed chunk hash despite a correct whole hash. A deterministic copy-race test
changes an unread source byte after the initial rehash/first copy buffer: the
candidate copy completes but final destination verification must refuse. This
explains why the final sealed rehash is mandatory, independently of source
metadata or a prior successful inspection.
