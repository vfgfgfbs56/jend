# M7.2.1 — lock-file compatibility fix

M7.2 introduced `subtle` only to compare a fixed 32-byte IPC capability in
constant time. That unnecessarily changed the dependency graph and made an
M7.1 `Cargo.lock` incompatible with the repository's `--locked` test policy.

M7.2.1 removes that dependency entirely. The comparison now uses a small safe
Rust fixed-length XOR accumulator over all 32 bytes. No early return depends on
the first mismatching byte, no `unsafe` is introduced, and the existing lock
file remains valid.

This preserves the important property: CI and local first-test runs stay
reproducible under `--locked` instead of silently mutating dependency state.
