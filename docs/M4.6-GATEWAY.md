# M4.6 — Rust HTTP Gateway

This milestone introduces the real network process without moving cryptographic policy into HTTP handlers.

## Boundary

`Cloudflare/edge -> jend-gateway (axum) -> jend-gateway-core -> PostgreSQL/control services`.

The HTTP process owns parsing, body/time limits, trusted-edge metadata normalization and routing. OPAQUE, DeviceSet, capability and model authorization stay in audited crates. No message plaintext API exists.

## Fail-closed state

M4.6 intentionally exposes only `/healthz` as operational. Registration admission returns 503 until the async PostgreSQL repository and shared/distributed rate-state are wired in M4.7. This is preferable to accidentally deploying an endpoint that bypasses anti-bot checks.

## Production requirements before enablement

- authenticated reverse-proxy hop; never trust forwarded IP/risk headers from arbitrary clients;
- async PostgreSQL repository with atomic username uniqueness and DeviceSet/model CAS;
- shared rate-state or edge+origin layered limits;
- admission challenge verification before OPAQUE registration start;
- uniform auth errors/timing where account enumeration matters;
- structured logs that never contain OPAQUE payloads, capabilities, recovery material, `.jend` ciphertext or plaintext;
- TLS at edge plus authenticated edge-to-origin transport;
- request IDs, bounded bodies, deadlines and graceful shutdown.
