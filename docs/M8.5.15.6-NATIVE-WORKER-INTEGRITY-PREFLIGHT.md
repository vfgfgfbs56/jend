# M8.5.15.6a — Native worker executable integrity preflight

**Status:** DEVELOPMENT-ONLY checksum preflight. NOT a worker code-signing
system, platform OS sandbox, process isolation, immutable executable handle
or real GGUF inference.

## Motivation

The user verified all **10** M8.5.15.5 GGUF verification/snapshot/lease
checks on Apple Silicon. These prove release-signed bytes and pinned
open-file identity, but do **not** prove the executable that eventually
loads model data can be trusted.

Before we hand private user prompts to any native C/C++ worker, the worker
binary itself needs an independently authenticated release identity, an
OS-enforced no-network/no-secret sandbox and bounded resources. This
milestone introduces the *file integrity preflight* while leaving all
production native execution blocked.

## Implemented

`client/jend-cli/src/native_worker_integrity.rs` exposes
`inspect_pinned_native_worker(candidate, independent_sha256, max_bytes)`:

- Requires an absolute path without `..` or `.` path components, a regular
  non-symlink final component, nonzero size and <=128 MiB hard cap.
- Refuses group/world-write bits on Unix executable itself.
- Opens exactly one file descriptor, checks its size (and Unix dev+inode)
  against the pathname preflight, streams SHA-256 with a fixed 64 KiB
  buffer and verifies exact byte count and signed expected digest.
- Returns only `NativeBinaryInspection` with byte length and digest.
  No public executable path/descriptor or method to execute a program.
- Deliberately does NOT use the downloaded binary itself, a file next to
  it, or a model publisher's unsigned metadata as a trusted expected digest.
- Pure Rust unit tests: matching pin, wrong pin, modified fixture, zero or
  over-limit size, relative path, final symlink and world-writable file.

An additional offline executable CMake + Rust smoke uses a **locally
compiled, model-free** `jend-gguf-cpu-worker`, derives its digest in the
TEST from local bytes, exercises rejection of a different expected digest
and tampering, then runs only `--protocol-smoke` via the previously
existing dev-only Rust IPC supervisor.

The test is NOT production key enrollment. Computing both sides of a
comparison from the same untrusted download provides NO provenance.
For a real product, independently pinned or signed Jend worker release
metadata must supply the expected SHA-256, OS code-signing identity and
allowed ABI. The trusted release and the binary must be bound to the
same independently verified installation policy.

## Native attack surface NOT solved here

**Do not use this helper to authorize production inference.**
- A checksum immediately before a spawn does NOT freeze the filesystem
  entry or prevent a same-user attacker from replacing the executable.
  `Command::new(path)` reopens a pathname; it is TOCTOU-prone.
- Executables can execute malicious instructions, open sockets, read disk,
  spawn helpers and access other processes if the OS has not blocked them.
  Environment clearing, stderr suppression and request timeouts are NOT
  an OS sandbox. Running this as the current user does not isolate secrets.
- Filesystem parent symlinks and per-user ACL policies are not wholly
  verified; Windows code signing, macOS hardened runtime and Linux
  namespaces/seccomp/landlock must be handled by platform backends.
- GGUF cache snapshots and held descriptors from M8.5.15.5 are likewise
  NOT immutably sealed backing memory and cannot yet be passed to C++.
- Android and iOS do not inherit this desktop subprocess launcher. They
  require platform-signed in-app native library wrappers and device tests.

## Next backend/security gates

1. Publisher/distributor independent worker-signing key trust enrollment,
   revocation and update rollback control.
2. Race-free pin of installed worker executable identity and immutable GGUF
   object at the OS level; full GGUF tensor metadata scanning.
3. Per-platform least-privilege worker execution: no network or secrets,
   bounded RAM/CPU/process tree, timeouts, cancellation and robust IPC.
4. Run a real independently trusted, licensed third-party GGUF model,
   measure RAM/latency/energy on supported x64 and ARM64 devices.
5. Stable model installation/generation/cancellation APIs with contract
   tests before the **Backend & Security Ready** frontend start gate.

The project frontend-start checkpoint is separate from **M8.5.16
architecture design freeze**. See root `JEND-PROJECT-CONTEXT.md`.
