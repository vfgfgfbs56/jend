# M7.12 — Provider Adapter + Network Broker boundary

M7.12 gives Store-selected models one execution-routing API while preserving
strictly different trust boundaries.

## Execution routing

`ChatExecutionRoute` resolves:

- `LocalPackage` -> isolated local AI executor;
- `VirtualPaged` -> isolated local AI executor / future WeightVM;
- `ProviderRemote` -> dedicated provider adapter.

Provider-backed models never enter `jend-aid` as if they were local models.

## Why the Network process still must not see chat plaintext

A closed provider necessarily receives the user's prompt, but Jend's generic
Network Broker does not need to.

The intended provider path is:

```text
Controller
   |
   | prompt
   v
Provider Adapter
   |  - holds provider HTTP semantics
   |  - receives an ephemeral credential lease
   |  - creates TLS request locally
   v
encrypted TLS records
   |
   v
Network Broker
   |  - registered provider host only
   |  - port 443 / public pinned IP only
   |  - opaque byte budgets
   |  - no prompt/API-key/response parsing
   v
Provider
```

The provider adapter is therefore a distinct future process, not code embedded
in the local model executor and not arbitrary Internet access granted to the
model.

## Two policy layers

### Adapter-local typed policy

Before TLS serialization, the adapter validates:

- provider identity;
- registered chat API path prefix;
- request-size cap;
- requested response-size cap.

Because the request becomes encrypted after this step, path enforcement is
defense-in-depth inside the provider adapter.

### Network Broker hard policy

The Network Broker can enforce what it can actually observe:

- one registered HTTPS hostname;
- DNS pinning to public addresses;
- no loopback/private/link-local/metadata targets;
- encrypted upload/download byte budgets.

It deliberately has no parser API for Authorization headers, prompts, or model
response plaintext.

## Credentials

M7.12 does not yet implement provider credential leases. The next provider
process milestone should let Vault issue a short-lived credential lease directly
to the provider adapter. The Network Broker receives neither the underlying API
key nor the plaintext Authorization header.

## No vendor hardcoding

M7.12 does not bake a specific OpenAI/Anthropic URL or API schema into Vault,
AI, or the Store model record. A signed/approved provider-adapter registry will
bind a provider ID to its current hostname/path policy. This keeps vendor API
changes outside security-critical local-model code.
