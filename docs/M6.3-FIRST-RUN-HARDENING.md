# M6.3 — First-run runtime/API hardening

Scope remains frozen around the first headless registration test.

## Trusted-device session early rejection

`POST /v1/auth/device/session/finish` now verifies the server HMAC and challenge
lifetime before any account or DeviceSet database lookup.

This prevents a previously issued but expired, otherwise authentic challenge
from being reused as a cheap PostgreSQL lookup trigger. Device signature
verification still checks the lifetime again as defense in depth.

The gateway unit test covers valid MAC, forged challenge, wrong server key,
exact-expiry acceptance, and post-expiry rejection.

## SQLx feature contract

Gateway and migration binaries now pin `sqlx = "=0.8.6"` before the first real
lockfile is generated and use the explicit SQLx 0.8 feature split:

- `runtime-tokio`
- `tls-rustls-ring-webpki`
- `postgres`
- plus `migrate` and `macros` for `jend-migrate`

The old combined `runtime-tokio-rustls` compatibility alias is no longer used.
