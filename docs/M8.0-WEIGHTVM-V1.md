# M8.0 — WeightVM v1

M8 begins the runtime technology for models whose logical weight space is much
larger than the device's chosen resident cache.

This milestone is deliberately narrow: it implements verified, bounded
**weight-page residency**, not neural-network execution yet.

## Core invariants

### Content-addressed pages

Each page is identified by SHA-256 of its plaintext bytes. Identical pages from
different releases can therefore share one resident cache entry.

### Verify on every page fault

A source page must match both its declared length and SHA-256 before becoming
resident. WeightVM does not trust a local cache merely because a file exists.

### No network client in WeightVM

`jend-model-store` still has no HTTP runtime dependency. `WeightPageSource` is a
local byte-source abstraction. Future authorized download/sync code places
signed/verified objects into a local content store; WeightVM consumes them.

This preserves the Jend rule that the local AI/weight runtime does not gain
arbitrary Internet access.

### Hard residency budget

WeightVM tracks resident bytes and evicts least-recently-used unpinned pages
when a page fault needs space.

Active `WeightPageLease`s pin their page. Tightening the cache budget never
invalidates an active lease. If pinned pages alone exceed the new budget,
WeightVM reports `over_budget_due_to_pins` instead of pretending it complied.

### Logical size is not active working set

The smoke uses metadata for a 500 GB logical model, a declared 16 GB active
working set, and a 4 MiB WeightVM cache. Six real 1 MiB test pages are faulted
through the cache.

That test proves *virtualized residency and eviction*. It does **not** claim that
a 16 GB active working set can execute efficiently from 4 MiB.

## Why this matters

Before M8.0, Jend could describe VirtualPaged models. After M8.0, Jend has the
first mechanism that actually enforces:

```text
logical weight space  >>  resident device cache
```

while preserving integrity and active-page safety.

## Next M8 milestones

M8.1 should add a durable content-addressed page store on disk plus crash-safe
indexing. M8.2 can add page ranges/model virtual mappings and prefetch hints.
M8.3 can connect Device Profiler / Runtime Governor signals to WeightVM budgets.
After that, a real inference backend can consume leases rather than assuming the
entire model is memory-resident.
