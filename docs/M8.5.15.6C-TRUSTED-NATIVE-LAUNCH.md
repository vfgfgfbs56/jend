# M8.5.15.6c — trusted pre-exec launch (model-free Linux experiment)

**Production inference remains BLOCKED.** This module is imported only by
`jend-native-trusted-launch-smoke`; the product does not use it. No model,
private chat, E2EE key or downloaded runtime is passed to this experiment.

## Trust boundary and fixed profile

The previous M8.5.15.6b.2 C++ probe applied `clearenv` / `close_range` after
the executable had already started. A hostile loader or constructor could
read inherited state first, or simply omit the restrictions.

The new Rust path prepares the process and kernel controls before `execveat`.
Only Linux x64 and ARM64 are implemented. The profile requires executable
memfd / execute-mode seals (Linux >= 6.3), Landlock ABI >= 3, close_range,
seccomp and an unprivileged parent with no effective/permitted/inheritable
capabilities. Root, set-ID and capability-bearing parents are refused.
Missing kernel controls, unsupported hosts or unsupported executable formats
fail closed; there is no weaker fallback. macOS, Windows, Android and iOS
require separate native OS adapters and currently refuse before file access.

1. The caller supplies independently enrolled `ReleasePolicy` and an already
   accepted `AcceptedReleaseHead`. Existing `jend-release` checks builder and
   approver signatures; admission requires exact statement ID, sequence,
   `LocalAiRuntime` kind and the host-specific model-free static profile.
   This launcher neither enrolls keys nor advances/persists a head.
2. Bound the artifact to 16 MiB; open once with O_NOFOLLOW / O_NONBLOCK,
   require a regular file and verify exact signed length/SHA256. Accept only
   native little-endian ELF64 ET_EXEC with bounded program headers, an entry
   in an executable segment, no W+X load segment, no PT_INTERP / PT_DYNAMIC.
   This is a narrow signed fixture profile, **not a general hostile ELF parser**.
3. Copy into executable memfd, set mode 0500 and seal WRITE / GROW / SHRINK /
   EXEC / SEAL. Re-read and verify the final immutable bytes. Opaque capability
   exposes neither a pathname nor FD. Subsequent inode mutation/path replacement
   cannot change the bytes executed by the kernel.
4. Allocate fresh input/output pipes and null stderr in the parent. Input is
   one constant harmless protocol frame, never an arbitrary user prompt.
   Build fixed argv and BPF instructions before fork. The child performs only
   audited syscall operations, with no allocations, logging, locks or unwinding.
5. In trusted child code: create a new session; install parent-death SIGKILL
   and check the parent-death race; replace all stdio; put sealed executable at
   FD 3 with CLOEXEC; set cwd `/`; apply hard limits, no_new_privs, Landlock
   empty filesystem allowlist, then close_range with UNSHARE for FD >= 4.
6. Install default-EPERM seccomp **before exec**. Check native audit ABI;
   exact syscall numbers also refuse x32. Forbid paths/open, network including
   AF_UNIX, process creation, signals to others, ptrace/process_vm, io_uring,
   descriptor creation/duplication, writable resource-limit updates and policy
   changes. Allow only the small static-runtime/self-memory/stdio syscall set.
7. Raw `execveat(3, "", ..., AT_EMPTY_PATH)` uses an empty environment and
   replaces all inherited address-space mappings. FD 3 closes at exec; only
   clean FD 0/1/2 remain. Restrictions already cover static libc startup and
   native constructors, independently of worker cooperation.
8. The parent drains bounded stdout without a blocking writer/reader thread,
   checks the wall deadline and always kills/reaps failure paths. Worker cannot
   create descendants. CPU spinner, non-reading stall and stdout flood have
   separate adversarial regressions.

## Two important OS details

Seccomp's `execveat` FD check alone is insufficient: an **absolute** pathname
ignores dirfd. A hostile program could call `execveat(3, "/bin/true", ...)`
even though FD 3 was closed. Mandatory Landlock EXECUTE denial closes this
path; constructor test requires actual EACCES for this attack. Empty-path
repeat requires EBADF, and seccomp forbids making a new FD or receiving one.
Anonymous memfd execution is outside the filesystem path hierarchy.

`PR_SET_DUMPABLE=0` applies to the trusted fork child, but ordinary exec can
reset dumpability. This experiment does **not** claim protection from an
external same-UID debugger/root, independent OS identity, kernel exploitation
or side channels. Native-to-parent memory/syscall access is denied. A separate
identity/service compartment and post-exec confidential process protection
remain production requirements; no real secrets enter this test.

## Quotas

| Resource | Fixed hard bound |
|---|---|
| Executable | 16 MiB |
| Address space | 128 MiB |
| CPU | 1 second |
| Open FDs | 4 during exec; 3 remain in worker |
| Stack | 8 MiB |
| Core / file growth / locked memory / process count | 0 |
| Stdout | 32 KiB |
| Wall time | caller 50 ms–5 s; fixture normally 3 s |

Own anonymous mappings/mprotect remain allowed for static libc; there are no
model or vault mappings. These bounds are a test profile, not measured budgets
for an inference engine, GPU driver or multithreaded backend.

## Verification and remaining gates

```bash
cargo generate-lockfile
python3 scripts/dev-native-trusted-launch-smoke.py
```

Linux tests require two-builder/two-approver synthetic signing, wrong
root/signature/head/kind/target rejection, dynamic ELF/symlink/oversize refusal,
and a hostile **constructor**, which itself installs no controls. Parent holds
a harmless non-CLOEXEC FD, synthetic environment and a sentinel anonymous
mapping at 0x100000000. Constructor checks absence and actual kernel denial
for file/network/process/memory/exec attacks, inability to raise limits, RAM
allocation rejection and active quotas. Unsandboxed constructor is a negative
control and must fail before main. Static C++ IPC still returns `NO_MODEL`.

CI runs the launcher on Linux x64/ARM64 and the refusal on both Mac runners
and Windows. Full workspace check/tests plus existing SQL/protocol regressions
remain required. Baseline SHA `0dfa02937d5abddf8b181e656471761e17d96a4b`
passed all 8 checks: [workspace/security](https://github.com/vfgfgfbs56/jend/actions/runs/38603544189),
[platform matrix](https://github.com/vfgfgfbs56/jend/actions/runs/38603544271),
[PostgreSQL](https://github.com/vfgfgfbs56/jend/actions/runs/38603544263).
Linux x64/ARM64 each show 10 trusted-launch PASS and 6 smoke unit tests;
Mac Intel/Apple Silicon and Windows each show 2 explicit refusal PASS.
The final hardening additionally tests ET_EXEC with PT_INTERP (independent
of PIE refusal), checks actual SIGKILL for the CPU spinner, uses a synthetic
FD/mapping portable to lower fd/address limits, and never gives the
unsandboxed negative control the real parent environment. ECHILD from an
external reaper does not trigger signaling a potentially reused PID.
Recheck current head CI after changes. No user Mac result is claimed.

The signing authorities are ephemeral **test keys**, not installed Jend
distributor trust. Persistent enrollment/rotation/revocation/rollback policy,
reproducible native release distribution, independent security review of the
unsafe syscall boundary, same-UID isolation, mobile/Apple/Windows adapters,
sealed GGUF handle handoff, parser/IPC fuzzing and a legal real model remain
open. JSEC-001/002/003/004/005/010/012 are **not CLOSED** by synthetic PASS.
