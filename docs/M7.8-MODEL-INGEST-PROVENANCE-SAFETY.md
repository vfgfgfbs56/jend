# M7.8 — Model ingestion, provenance and safety quarantine

Jend Store never treats an arbitrary user-supplied URL as an installation
authority. External locations exist only on the Store ingestion side.

## Supported ingestion origins

### Hugging Face snapshot

The ingest record stores:

- repository ID;
- full immutable 40-hex commit SHA;
- license evidence;
- fetched artifact digests.

`main`, branches, tags and short SHAs are not persisted as the final authority.
An ingestion service may accept a friendly revision initially, but it must
resolve it to an immutable commit before scan/publication.

### Publisher HTTPS

Jend stores validated host/path components plus expected SHA-256. The downloader
uses the typed Network Broker; the model-store layer never authorizes arbitrary
schemes, query strings, fragments or path traversal.

### Existing Jend object

Already-ingested content-addressed objects may be reused directly.

## License gate

Hub/model-card metadata is evidence, not a legal oracle. A release needs an
explicit redistribution decision (`Approved`, `ProviderOnly`, `PendingReview`,
or `Rejected`). Local/virtual weight publication proceeds only when approved.

## Supply-chain quarantine

Every artifact is quarantined until all required checks succeed:

1. immutable source;
2. digest verification;
3. redistribution approval;
4. malware scan;
5. safe parser/format scan;
6. no publisher-controlled executable/custom model code.

Jend Store rejects direct pickle/PyTorch-pickle packages and custom remote code.
If a legacy pickle model is important, a future disposable offline conversion
service may inspect it without trusting/executing it and emit a *new* data-only
release (e.g. safetensors/GGUF) with new hashes and a new scan attestation.

Preferred data-only formats include safetensors, GGUF, ONNX and Core ML, but
being data-only does not make a parser bug impossible. Parsing/conversion must
still happen in a resource-bounded sandbox.

## Behavioral security

File scanning does not prove the model itself is safe. A second isolated
evaluation gate records:

- backdoor/trojan probes;
- prompt-injection resistance;
- tool-abuse behavior;
- data-exfiltration probes;
- malformed/hostile output behavior.

Outcomes are `Approved`, `Restricted`, `Quarantined`, or `Rejected`. A
Restricted listing may be published only with explicit runtime restrictions
(e.g. no tools/network or stronger confirmation).

## Store ingest flow

```text
publisher/hub
   -> immutable revision
   -> quarantine
   -> license/provenance
   -> digest + malware + parser scan
   -> safe offline load
   -> behavioral eval
   -> Jend conversion/quantization (optional)
   -> new hashes
   -> signed Jend manifest
   -> catalog publication
```

Model files never become trusted because an upstream hub says "clean". Upstream
scanner results are additional evidence; Jend repeats/augments the checks under
its own publication policy.
