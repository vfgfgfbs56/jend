# M8.5.11 — Bounded Xet multipart decode and opt-in live probe

## What landed

1. `xet_multi_decode.rs` consumes only bounded, already strictly validated
   `UntrustedXorbPhysicalRange` parts. Before decompressing it verifies
   xorb identity (64-byte lowercase hexadecimal), exact declared physical
   length, valid chunk spans, no duplicate chunk coverage and the aggregate
   physical byte budget. Decoding uses the existing bounded Xorb v0
   None/LZ4/BG4 decoder and a single aggregate decoded-byte budget.
2. `jend-xet-multipart-decode-smoke.rs` assembles a wholly offline synthetic
   signed reconstruction through the M8.5.10 strict multipart HTTP 206 gate,
   bounded xorb decoder and M8.5.7 multi-range logical assembler. It refuses
   HTTP 200 fallback and writes no logical data to disk/WeightVM.
3. `jend-hf-xet-multipart-live-smoke.rs` adds a separate, EXPLICIT opt-in live
   network probe against the immutable
   `openai-community/gpt2@607a30d783dfa663caf39e06633721c8d4cfcd7e`
   `model.safetensors` Xet identity. It asks for only the first **1 MiB**
   logical reconstruction and permits at most **8 MiB** physical payload,
   **128 KiB** multipart framing and **16 MiB** decompressed data. There are
   no retries, cross-origin redirects, URL forwarding or automatic fallback.
4. The live test only executes if reconstruction metadata yields EXACTLY ONE
   signed fetch entry containing at least TWO authorized physical ranges.
   If the real source does not meet this shape, it prints **SKIP** and exits
   without xorb fetch or forged success. This is not a failure of the
   cryptographic page gate; it means this test fixture is ineligible.

## Mac offline test (no token required)


Expected:

```text
Jend Xet multipart physical-to-logical offline pipeline: PASS
Jend Xet decoded data kept outside WeightVM: PASS
Jend Xet untrusted multipart fallback rejected: PASS
```

## Mac live test (only by explicit user choice)

The live test uses public signed Xet routes but calls authenticated Hub/CAS
metadata endpoints. It will transfer real network bytes only with BOTH:

- `JEND_ALLOW_LIVE_HF_XET_MULTIPART=1`
- `JEND_HF_TOKEN` set to an HF read-only token for the chosen model.

Never paste the token into chat, logs, command line arguments or `bash -x`
output. Use a local shell variable/secure injection method and avoid enabling
shell tracing. Run:

```bash
JEND_ALLOW_LIVE_HF_XET_MULTIPART=1 bash scripts/dev-hf-xet-multipart-live-smoke.sh
```

A complete live `PASS` is only printed after actual HTTP 206, strict
multipart parsing, physical xorb decoding and full one-megabyte logical
reconstruction. If the source metadata is ineligible, `SKIP` is the correct
outcome. HTTP errors, Xet schema drift and invalid length/status must fail
closed and be reported, without untrusted byte publication.

## Still blocked

**This is not verified WeightPage delivery.** Physical Xorb bytes and decoded
logical bytes are not cryptographic Jend weight claims. Until a separate
release-signed page digest and exact length validate the assembled page,
WeightVM must never use or publish the output. Live multi-entry fetch waves,
multi-origin routing, source sandbox and signed multi-region routing also
remain future work. M8.5 is incomplete.

The live binary has **not been executed against HF/Xet by GitHub CI**.
The offline tests can pass even when the live fixture returns SKIP or fails.
