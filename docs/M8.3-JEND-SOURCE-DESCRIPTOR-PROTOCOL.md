# M8.3 — Jend Source Descriptor Protocol (JSDP) v1

M8.3 separates **model identity** from **model transport**.

WeightVM continues to trust only `WeightPageId = SHA-256(page bytes)`. It does
not know Hugging Face URLs, publisher URLs, credentials, HTTP, Xet, mirrors or
peers. Instead, Store releases can carry a signed source map that says which
immutable source byte ranges are candidates for a particular page.

## Core structure

```text
WeightPageId / expected length
        │
        ▼
SignedModelSourceMap
        │
        ├── SourceDescriptor(HuggingFaceXet)
        ├── SourceDescriptor(PublisherHttps)
        └── SourceDescriptor(JendObject)
        │
        ▼
PageSourceBinding(source_id, offset, expected page)
        │
        ▼
SourceReadRequest  (URL-free, credential-free)
        │
        ▼
future source adapter
        │
        ▼
bytes → SHA-256 verification → DurableWeightPageStore → WeightVM
```

## Why this is not an HF dependency

`HuggingFaceXet` is one adapter-facing origin type, not a WeightVM API. A future
HF/Xet implementation may change without changing the virtual model map,
WeightVM cache, AI executor or local inference interface.

`SourceReadRequest` contains only:

- `SourceId`;
- byte offset;
- bounded length;
- expected `WeightPageDescriptor`.

It deliberately contains no URL string and no credential.

## Immutable source rules

HF descriptors require a full 40-character lowercase hexadecimal commit SHA.
`main`, `latest`, short SHAs and path traversal are rejected.

Publisher HTTPS descriptors use validated host and immutable path components;
the protocol never accepts an arbitrary URL supplied by a model or end user.
Actual DNS/SSRF/TLS enforcement belongs in the future isolated source adapter /
Network Broker, not in WeightVM.

## Multi-origin without changing page identity

One `WeightPageId` may have multiple bindings. This is intentional:

```text
same page hash
  ├── HF/Xet immutable range
  ├── publisher immutable range
  ├── future Jend mirror
  └── future P2P peer
```

M8.3 only models and signs candidates. It does not yet choose/race them; that is
planned for the multi-origin resolver milestone.

## Signed source map

The existing model release Ed25519 key now signs source maps with a separate
domain:

`JEND/MODEL/SOURCE-MAP-SIGNATURE/V1`

Changing a range offset, source descriptor, object length, expected page or
release sequence changes the canonical map ID and invalidates the signature.

## Security boundary

A valid source-map signature does **not** make an upstream source trusted. The
returned bytes still must hash to the expected `WeightPageId` before they can be
published to the durable store or become resident in WeightVM.

M8.3 contains no network client and adds no HTTP runtime dependency.

## Next

M8.4 should implement the first real adapter: a constrained HF/Xet metadata and
range client behind the existing Network Broker rules. It should translate a
signed `SourceDescriptor + SourceReadRequest` into upstream operations, enforce
host/DNS/redirect/byte/time limits, and return untrusted bytes for page-hash
verification.
