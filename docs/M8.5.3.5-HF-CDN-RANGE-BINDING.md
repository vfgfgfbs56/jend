# M8.5.3.5 — HF CDN reconstruction-range binding

A live HF/Xet CAS response demonstrated that current `us.aws.cdn.hf.co`
direct-xorb URLs can omit `X-Xet-Signed-Range` while retaining a CloudFront
signature envelope (`Expires`, `Policy`, `Signature`, `Key-Pair-Id`).

Policy is now deliberately split:

- `transfer.xethub.hf.co` / `transfer.xethub-eu.hf.co`: exact xorb path, exact
  expected hash, and `X-Xet-Signed-Range` are required.
- `us.aws.cdn.hf.co` / `us.gcp.cdn.hf.co`: exact allowlisted host, exact
  hash-bound direct-xorb or bridge path, and complete CloudFront signature
  envelope are required. `X-Xet-Signed-Range` is optional for this profile.

The exact byte ranges remain part of the authenticated CAS reconstruction
metadata (`xorbs.*[].ranges[].bytes`). Future xorb transport MUST construct the
HTTP `Range` header only from those validated descriptors; it must not allow a
caller to supply arbitrary ranges.

This milestone still does not execute signed xorb URLs or download weight
payloads.
