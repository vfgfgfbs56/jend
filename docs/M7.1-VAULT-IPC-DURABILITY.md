# M7.1 — Vault IPC durability and liveness

This checkpoint turns the first Vault daemon boundary into something that can
be exercised end-to-end as a separate process.

## Added

- reusable Unix `VaultIpcClient` for future UI/runtime workers;
- bounded 16 MiB request *and response* frames;
- five-second socket read/write deadlines on accepted clients;
- private `0700` Vault state directory;
- IPC request for the device public identity only (private keys never leave);
- process smoke that creates a conversation, appends and reads plaintext through
  Vault, restarts the daemon, then proves both encrypted history and the device
  signing identity survived unchanged;
- fail-closed checks for an already occupied socket path and for a public IPC
  directory;
- `cargo test -p jend-vault --locked` in the first-test ladder.

The client is synchronous by design and must be called from a worker/runtime
queue, never the UI/render thread. M7.2 will tighten peer authorization; this
checkpoint still does not claim isolation from malware already executing as
the same OS user.

Run after `first-test-ladder.sh`:

```sh
bash scripts/dev-vault-ipc-smoke.sh
```

Expected final lines include:

```text
Jend Vault durable identity/history: PASS
Jend Vault IPC process smoke: PASS
```
