# M5.9 — First-run schema and dependency contract

This checkpoint reduces two classes of first-run ambiguity.

## Database readiness

The gateway now refuses startup unless:

- all gateway state tables exist;
- critical columns have their expected PostgreSQL types;
- SQLx's migration table exists;
- no SQLx migration is marked failed;
- the latest successful migration is exactly version 6, matching the bundled
  migration directory.

This is intentionally fail-closed. A binary built for migration 6 should not
silently operate against a newer, unknown schema.

## Dependency resolution

The source archive still cannot contain a truthful Cargo.lock because Cargo has
not run in the current build environment. On the first real runner, `cargo
metadata` creates the lock file. Every subsequent build/check/test step in that
run uses `--locked`, so the compiler, unit tests and PostgreSQL smoke test see
the same dependency graph.

## Local first-run helpers

- `scripts/doctor-headless.sh` checks the static contract, repository manifest
  integrity and required local tools without starting services.
- `scripts/dev-headless-smoke.sh` starts the localhost PostgreSQL compose
  service and runs the full registration/login/JREQ security smoke in one
  command. Set `JEND_DEV_CLEANUP=1` if the development database should be
  removed automatically afterward.

## Verification boundary

This environment still has no usable Rust/PostgreSQL runner, so M5.9 remains a
preflight/source checkpoint. The first external `cargo check --locked` and DB
smoke result remains the acceptance gate.

The source manifest intentionally ignores `.git/`, `target/`, generated
`Cargo.lock`, `resolved-metadata.json`, and the local development secret
directory. It continues to reject unexpected changes/additions in the packaged
source tree.
