# M8.5.3.4 — HF CDN direct-xorb path compatibility

Live CAS reconstruction reached an allowlisted HF CDN host but returned a
direct Xet xorb path (`/xorbs/default/<hash>`) rather than only the older/other
`/xet-bridge-us/<opaque>/<hash>` path assumed by M8.5.3.3.

This patch keeps the host allowlist exact (`us.aws.cdn.hf.co`,
`us.gcp.cdn.hf.co`) and accepts only hash-bound path profiles:

- `/xorbs/default/<expected hash>`
- `/xorb/default/<expected hash>`
- `/xet-bridge-us/<bounded opaque id>/<expected hash>`

Direct xorb CDN URLs additionally require `X-Xet-Signed-Range` and the CDN
signature envelope (`Expires`, `Policy`, `Signature`, `Key-Pair-Id`). Bridge
URLs retain the CDN signature-envelope requirement. No wildcard host/path is
introduced. Signed URLs are still metadata-only and are not executed by the
M8.5.3 live reconstruction smoke.
