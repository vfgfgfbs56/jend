# M8.5.15.2 — Cross-device native runtime protocol portability

Status: PROTOCOL-ONLY cross-platform proof. No third-party GGUF inference,
production native worker sandbox or mobile neural-network engine is claimed.

## Devices are the actual Jend product scope

Jend is a universal interface to existing, licensed third-party AI models,
not a Mac-only product and not a project to train a new model.

| Target | Expected architecture | Native strategy | This PR's proof |
| --- | --- | --- | --- |
| Windows desktop | x86_64, later ARM64 | pinned C++ CPU worker; later Vulkan / CUDA / DirectML where compatible | native MSVC C++ and Rust protocol on Windows x64 CI |
| Linux desktop | x86_64 and ARM64 | pinned C++ CPU worker; later Vulkan / CUDA / HIP | native C++ and Rust protocol on Linux x64 + ARM64 CI |
| macOS desktop | Intel x86_64 and Apple Silicon ARM64 | pinned C++ CPU worker; later Metal with Objective-C++ glue | native C++ and Rust protocol on both macOS architectures CI |
| Android | ARM64 primary, x86_64 for emulators | signed in-app library or OS-specific isolated service; CPU/NNAPI/Vulkan if proven | standalone Rust wire parser cross-compiles; desktop spawn explicitly denied |
| iPhone / iPad | Apple ARM64 | app-signed in-process engine with OS entitlements; Metal / Accelerate where supported | standalone Rust wire parser cross-compiles; desktop spawn explicitly denied |
| Future OS/device | capability-detected | no assumption that binaries or GPU kernels are portable | fail closed until a dedicated platform implementation exists |

The test matrix uses GitHub-hosted runners for a PUBLIC repository. The
Rust mobile-target job emits metadata only: it does NOT link, run or sign a
native Android/iOS app. Mobile resource, ABI and sandbox policies need device
farm tests and appropriate signed application builds before support claims.

## Hard portability invariants

- One versioned length-bounded binary protocol independent of host endianness,
  OS, Unicode command-line encoding and filesystem separators.
- CMake uses MSVC-native /W4 /WX on Windows and Clang/GCC flags elsewhere.
- The test script locates single- or multi-configuration generator output,
  including Windows .exe and Visual Studio Debug paths.
- Rust parent and C++ worker exchange the same bytes and reject truncated,
  oversized, appended or second messages on every tested desktop.
- C++ production inference and the dev-only GGUF load path remain DISABLED
  in the portability matrix; no model fetch or HF credentials.
- No downloaded model can select a native executable. Signed artifact
  admission stays separate from OS-specific backend permission.
- Android and iOS cannot run the DESKTOP dev process supervisor. Their own
  separately reviewed native integration is required. No fork/exec reliance
  and no assumption of unrestricted child-process/sandbox privileges.
- CPU ISA-specific NEON, AVX2, AVX512, AMX and GPU shaders need explicit
  runtime capability checks, numerical conformance tests and real-device
  performance measurements. Assembly must never be a prerequisite for
  baseline inference; a portable CPU fallback is essential.
- iOS has app-store signing and dynamic code loading restrictions; Android
  has APK/NDK ABI and service/process limits. Neither can reuse a desktop
  process binary without a platform-specific security design.
- GPU provider availability and inference readiness cannot be inferred
  from this protocol CI. They still require real model test weights,
  backend-version compatibility, power/thermal and RAM profiling.

## Developer tests

On any supported desktop with CMake, C++17, Python 3.12, and Rust 1.99.0:

    python scripts/dev-native-gguf-cross-platform-smoke.py

This compiles the protocol-only C++ worker, tests canonical framing and
denial cases, compiles and runs standalone Rust IPC unit tests, and runs
the Rust-to-C++ supervisor. The use of standalone rustc intentionally
avoids linking unrelated server/backend workspace crates that may not be
portable. The earlier full-workspace Ubuntu CI continues to run separately.

CI workflow:
    .github/workflows/native-ipc-portability.yml

Independent tests are five desktop OS/CPU runner types and one cross-compile
job for Rust wire-parser compatibility on iOS and Android ARM64.

Expected desktop test lines:

    Jend portable C++ worker compiled on actual host: PASS
    Jend portable C++ framed IPC is byte-identical: PASS
    Jend portable C++ rejects truncation and second frames: PASS
    Jend portable native inference disabled by default: PASS
    Jend portable Rust wire parser unit tests: PASS
    Jend portable Rust-to-C++ one-shot supervisor handshake: PASS
    Jend cross-platform proof is protocol-only; no model inference: PASS

Do not equate successful Linux, Windows or macOS CI with support for
production GGUF inference: worker executable attestation, OS-specific
sandbox, signed full GGUF package, actual backend load and resource
benchmarks remain release blockers.
