# M7.3 — Runtime scheduler and latency budgets

M7.3 adds the first reusable local scheduling primitive for Jend's requirement
that message interaction stay responsive while local AI is busy.

## Priority lanes

1. `UiInteractive` — input, optimistic message insertion, animation state.
2. `VaultCritical` — encryption/decryption, durable commit, key operations.
3. `SyncInteractive` — foreground synchronization.
4. `AiForeground` — visible local inference.
5. `Background` — indexing, cleanup, prefetch.

Submission uses `try_submit`: it never waits for queue capacity. Each lane is
bounded, with deliberately small AI/background defaults on memory-constrained
devices. When a lane is full, the original task is returned so a caller can
coalesce, retry, or drop work intentionally.

## Queue-wait budgets

The initial queue-wait targets are 8 ms (UI), 20 ms (Vault), 50 ms (sync),
100 ms (foreground AI), and 500 ms (background). These are telemetry/adaptation
budgets, not claims that every task itself completes inside the budget.

Strict priority can permanently starve inference, so after at most eight
consecutive urgent dequeues the scheduler gives one pending AI/background task
a fairness slot. UI still dominates under load.

## Device adaptation hook

`RuntimeSnapshot` exposes bounded queue depths and pressure (`Idle`, `Normal`,
`Elevated`, `Saturated`). M7.4 can combine this with CPU/memory/thermal device
profiling to reduce AI concurrency or animation quality before frame latency
becomes visible.

## Lock-file policy

The scheduler currently lives in `jend-vault` to avoid adding a new workspace
package and invalidating the proven M7.2.3 `Cargo.lock`. Once the runtime API is
stable, it can be extracted into `jend-runtime` as one intentional baseline
change.
