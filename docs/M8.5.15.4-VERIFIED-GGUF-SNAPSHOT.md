# M8.5.15.4 — release-signed GGUF private snapshot store

Status: **offline model-byte snapshot proof; NOT immutable against the device
owner, not a kernel-pinned handle, not a production inference permission.**

## Background

On macOS ARM64 the user confirmed six M8.5.15.3 checks: independent
release-signature inspection, wrong signer and tampered manifest rejection,
corruption and truncation rejection, header refusal, bounds and lack of
native execution. Jend is a **universal interface for existing models**
and must preserve these integrity properties on every OS.

M8.5.15.3 verified bytes at a mutable path but returned an inspection
receipt. An attacker or updater could modify the original immediately after
the check. We cannot simply pass the original path to llama.cpp.

## What this milestone implements

The new `VerifiedGgufSnapshotStore` in
`crates/jend-model-store/src/gguf_snapshot.rs`:

1. Accepts a locally configured absolute *private cache root*, a pinned
   independent `ModelReleasePublicKey`, a `SignedModelManifest` and a
   local source path. It does NOT choose the key from any downloaded file.
2. Verifies the signature **before opening** the untrusted source.
3. Checks manifest GGUF and caller limits (up to 16 GiB), preflights
   regular non-symlink source and exact expected length.
4. Copies the untrusted source using a fixed 64 KiB RAM buffer into a
   fresh random `create_new` staging file within the private cache.
5. Calls the prior `inspect_independently_signed_gguf` on the
   **staged copy**, checking signed chunk SHA-256, whole-file SHA-256,
   GGUF v3 prefix, length and caller bounds.
6. Atomically publishes a content-hash filename in the local `objects`
   folder via a same-filesystem **hard link with no overwrite**.
   No failed verification produces a published object; staging aliases
   are removed automatically on errors.
7. Re-opening a cache hit verifies the stored bytes against the signed
   manifest again rather than trusting the hash-like name alone.
8. On Unix, private root/staging/objects directories must have no group
   or world permission bits; snapshot file uses read-only owner mode.
   On Windows the file is marked read-only *after* deleting the staging
   alias because NTFS hardlinks share permissions. Windows directory
   ACLs are NOT validated by this experiment.

The snapshot copy no longer depends on the original source file: if the
original changes or is removed after publication, the published copy
retains the signed bytes. Storage is **content-addressed**, so verified
identical model artifacts can reuse their bytes across releases, subject
to future license/account policy.

## Security limitations and precise meaning

- This is not an OS-enforced immutable file. The owner, administrator,
  malware running as the owner, or a privileged process may still modify
  the final path, its parent directory or file metadata after verification.
- The caller must supply a safe root from Jend's local application storage
  policy; this prototype does not verify every parent component or apply
  cross-platform owner UID / Windows DACL enrollment.
- The returned `VerifiedGgufSnapshot.path` is **not a native worker
  capability**. There is no direct bridge to `--infer-dev`, WeightVM
  residency or app plaintext chat. Loading requires a later race-free
  OS-specific read-only file-descriptor/handle broker, final verification
  on that handle, native worker attestation and platform sandbox.
- `hard_link` fails closed on filesystems where hardlinks are forbidden
  or unavailable. We do not silently substitute unsafe overwrite/rename.
- The GGUF v3 prefix check remains basic; it is NOT a complete schema,
  tokenizer, quantization, tensor-shape or malicious data audit.
- The fixture self-generates an ephemeral signing key ONLY for test
  repeatability. Production needs independently enrolled publisher or
  trusted distributor keys and real signed releases.
- This stores only the user's **selected local models**, not a central
  Jend repository of terabytes. Download/provider network and P2P sources
  cannot change the signed expected content identity.
- The test works entirely offline, with no model weights, HF token or
  actual neural inference.

## Mac offline test

```bash
bash scripts/dev-verified-gguf-snapshot-smoke.sh
```

Expected six lines:

```text
Jend GGUF independent release signature to private snapshot: PASS
Jend GGUF source mutation cannot modify verified copy: PASS
Jend GGUF different release key rejected before staging: PASS
Jend GGUF corrupted copy leaves no published or staged file: PASS
Jend GGUF explicit snapshot size budget enforced: PASS
Jend GGUF snapshot grants no native execution capability: PASS
```

## Next engineering gates

1. Add explicit tested production trust root for a licensed small
   third-party GGUF variant, not a key generated at download time.
2. Constrain a platform-specific **stable native read-only handle** from
   this checked store; verify SHA-256 on that handle, prevent symlink,
   hardlink and TOCTOU replacement through OS primitives.
3. Signed/pinned native worker executable with CPU/OS RAM limits,
   filesystem sandbox and mandatory no-network permissions.
4. CPU-only real model token generation on x86-64 and ARM64 with full
   GGUF architecture compatibility checks, tokenizer handling and
   measured RAM/latency.
5. Integrate Android/iOS with app-signed native libraries and separate
   mobile OS security constraints rather than desktop subprocess assumptions.
