# M8.5.9 — Strict offline Xet multipart/byteranges parser

This milestone adds a **transport-independent parser only**. It does not enable
multi-range HTTP execution, bypass the single-range transport contract, or
publish any model weights.

## Security contract

- Input is a body already bounded by the source worker and a Content-Type value.
- The caller must separately enforce HTTP 206 and derive every authorized byte
  range from one signed Xet reconstruction fetch entry.
- Only strict multipart/byteranges with an ASCII boundary is accepted.
- Each part requires a valid Content-Range with an explicit resource length.
- Every returned range must match one authorized byte span exactly; missing,
  duplicate, unsolicited or overlapping authorizations are rejected.
- Header fields are allowlisted; content encodings, folded headers, extra
  headers, preamble, epilogue and stray bytes are rejected.
- The parser uses explicit Content-Range lengths to consume binary payloads,
  not delimiter scanning through decoded model bytes.
- The 16 MiB payload, 128 KiB framing and 512-part hard ceilings cannot be
  enlarged through caller-provided limits.
- No partial page bytes are returned on any failure. Output order is the
  signed authorization order, regardless of multipart part order.

## Test targets

`client/jend-cli/src/xet_multipart.rs` includes Rust tests for good data,
reordered parts, duplicate/missing/extra ranges, malformed lengths/headers,
trailing bytes, budget violations, injected Content-Type, overlapping source
ranges and delimiter-like bytes embedded in the binary payload.

The existing `jend-xet-fetch-schedule-smoke` now exercises one synthetic
multipart body against its signed fetch schedule. Tests have not been run
in this authoring environment; green Cargo/CI execution is required.

## Deliberately deferred

Live multipart transport remains fail-closed in `source_worker_transport.rs`.
Future activation must combine exact signed authorization, HTTP 206,
bounded response streaming, header and payload limits, the parser above,
Xorb decoding, multi-Xorb assembly and **independent signed Jend page hash
verification** before durable WeightVM admission.
