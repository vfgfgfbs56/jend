# M6.2 — First test ready checkpoint

This milestone is the handoff from architecture/preflight work to the first
real headless execution attempt.

## Confirmed compile-oriented fixes in this increment

1. `jend-jreq::Request` is now `Clone + Copy`. The negative tampering tests use
   Rust struct-update syntax more than once from the same request; without Copy
   the second case is a use-after-move compile error.
2. `jend-auth` now depends explicitly on `rand 0.8.5` and imports
   `rand::rngs::OsRng`. `opaque-ke 4.0.1` re-exports its `rand 0.8` dependency,
   but that dependency is declared with default features disabled; relying on
   that re-export does not itself guarantee `OsRng` is available.

The dependency and static-preflight policies enforce both contracts.

## First test boundary

At this point the next useful activity is a real compiler/database run, not
additional security architecture.

On a machine with Rust 1.99.0, Docker and curl:

```bash
bash scripts/doctor-headless.sh
JEND_DEV_CLEANUP=1 bash scripts/dev-headless-smoke.sh
```

The smoke runner is expected to perform migrations, key generation, fail-closed
public-bind testing, gateway readiness, OPAQUE registration/login, first-device
activation, JREQ proof-of-possession, replay rejection, capability refresh and
trusted-device session login.

## Meaning of failure

A compiler error from this run is now actionable M6.x work: fix the concrete
error and rerun. A PostgreSQL or HTTP smoke failure is likewise a runtime bug to
repair. Do not respond by adding new product architecture unless the failure
actually exposes a missing security invariant.

## Verification status

The current preparation environment still has no Rust/Cargo/Docker runtime, so
this revision is **first-test ready**, not **build verified**. A green result
requires `cargo check/test` plus the PostgreSQL smoke runner on an external
machine or CI runner.
