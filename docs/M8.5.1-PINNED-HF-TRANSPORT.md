# M8.5.1 — Pinned HF/Xet HTTPS transport

M8.5.0 established the bounded response/DNS contract. M8.5.1 adds a real
HTTPS transport executable target while keeping `jend-model-store` network-free
and leaving Cargo.toml unchanged, so the existing lockfile remains reusable.

## Hardened transport builder

The worker never uses `reqwest::Client::new()`.

It constructs a client with:

- HTTPS-only requests;
- no system/environment proxy;
- redirects disabled;
- Referer disabled;
- finite connect and whole-request deadlines;
- explicit DNS resolution before client construction;
- fail-closed rejection if **any** returned DNS address is special/non-public;
- `resolve_to_addrs(host, pinned_addresses)` so the socket destination cannot be
  re-resolved after validation while the URL hostname remains intact for TLS
  SNI and certificate-name verification;
- closed HF/Xet host allowlist;
- streamed response-byte accounting;
- strict `206 Partial Content` for exact byte ranges; `200 OK` is rejected;
- no automatic compression features in the existing reqwest dependency.

Bearer tokens are wrapped by a non-Debug `Zeroizing<String>` type.

## Live smoke

The explicit live smoke uses public `openai-community/gpt2`, immutable commit
`607a30d783dfa663caf39e06633721c8d4cfcd7e`, and `model.safetensors`.
It sends only a resolve-discovery request (`Range: bytes=0-0`) with redirect
following disabled and requires a valid 64-lower-hex `X-Xet-Hash`.

The live test is opt-in:

```bash
JEND_ALLOW_LIVE_HF=1 bash scripts/dev-hf-source-worker-live-smoke.sh
```

This milestone does **not** download the model weights.

## Still not implemented

- authenticated private IPC from the controller/Store into the worker;
- OS sandbox/seatbelt/seccomp rules;
- Xet read-token JSON parsing;
- CAS `/v2/reconstructions` JSON parsing;
- signed multi-range xorb download and `multipart/byteranges` parsing;
- xorb chunk decompression/reassembly;
- WeightPage SHA-256 verification and atomic durable-store commit.

Those belong to M8.5.2+.
