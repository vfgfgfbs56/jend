# M5.8 — fail-closed startup and complete readiness contract

This increment narrows the gap between source-complete authentication and a
safe headless first launch.

## Database contract

`jend-gateway` now uses the same required-schema check at startup and `/readyz`.
The contract covers every PostgreSQL table currently referenced by the gateway
repository:

- accounts
- device_sets
- admission_buckets
- admission_used_challenges
- login_ip_buckets
- login_account_buckets
- consumed_login_tickets
- registration_device_bootstraps
- consumed_device_binding_challenges
- consumed_jreq_nonces

The process exits before binding a socket when this schema is incomplete. This
prevents a misleading `ready` state after partial migrations.

## Plain HTTP bind guard

The headless gateway still has no built-in TLS termination. Therefore it now
refuses a non-loopback `JEND_GATEWAY_ADDR` by default. Local smoke runs on
`127.0.0.1` require no override.

`JEND_ALLOW_INSECURE_HTTP=1` exists only for an explicitly isolated development
network. It is not a production TLS substitute. A production reverse proxy
should terminate TLS and normally connect to a loopback/private gateway bind.

The CI smoke harness includes a negative startup assertion: `0.0.0.0` without
the override must exit rather than listen.

## Verification status

Static preflight, manifest/TOML checks and shell parsing can run in the current
execution environment. Rust compilation and PostgreSQL execution still require
a runner with the Rust toolchain and database runtime.

## First dependency lock capture

This pre-compile archive does not fabricate a `Cargo.lock`. The first hosted CI
run performs `cargo metadata`, which resolves dependencies using the pinned Rust
toolchain and uploads both the generated `Cargo.lock` and resolved metadata.
That lockfile should be reviewed and committed in the next revision before the
baseline is called reproducible. Failure logs from the gateway smoke path are
also preserved under `target/jend-ci` as a CI artifact.

The local Compose and hosted CI PostgreSQL images are aligned on the same major
(`postgres:17-alpine`) to remove an unnecessary source of environment drift.
