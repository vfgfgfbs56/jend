# M8.2 — Signed Virtual Model Address Map + Expert Map

M8.0 introduced bounded RAM residency. M8.1 introduced durable content-addressed
page storage. M8.2 adds the missing address layer that says **which pages form
which logical part of a model**.

## Signed logical map

A `VirtualModelMap` binds one model release to ordered regions:

```text
region 0  shared backbone  -> page IDs...
region 1  router           -> page IDs...
region 2  coding expert 17 -> page IDs...
region 3  reasoning 42     -> page IDs...
```

Regions cover a contiguous logical weight address space. Every region's declared
length must exactly equal the sum of its page lengths. Expert IDs are unique.

The canonical map receives a domain-separated SHA-256 `VirtualMapId`, then is
Ed25519-signed with the model release key under a separate virtual-map signature
domain. This prevents a tampered cache/catalog from redirecting an expert to
other weight pages while keeping the same model name.

## Router-facing expert lookup

The runtime can now ask:

```text
experts_for_role(Coding) -> [ExpertId(17)]
pages_for_expert(17)     -> mandatory expert pages
prefetch_pages_for_expert(17)
                          -> backbone/router hints + expert pages
```

Prefetch hints are only hints. They never bypass WeightVM's resident-byte budget
or active-page pinning rules.

## Warm-up ordering

M8.2 returns hinted dependency pages first and selected-expert pages last. With
an LRU cache this keeps the selected expert hottest after warm-up while still
making the shared backbone/router available.

## End-to-end smoke

The smoke creates six real 1 MiB durable objects:

- 1 MiB shared backbone;
- 1 MiB router;
- 2 MiB coding expert;
- 2 MiB reasoning expert.

It signs and wire-roundtrips the map, resolves coding expert 17, creates its
4-page warm-up plan, reopens the durable store, and materializes exactly 4 MiB
through WeightVM. It then mutates the signed expert ID and requires signature
verification to fail.

This is the first direct path:

```text
router decision -> ExpertId -> signed page map -> durable store -> WeightVM
```

No neural router is implemented yet; the decision is still supplied by the
caller.

## Next

M8.3 should add a small deterministic expert-selection router contract and
runtime prefetch scheduler. It should take capability signals (coding/reasoning,
possibly token/context features), select top-k experts, and warm their pages
without blocking the UI thread. Later the deterministic policy can be replaced
by a learned local router while retaining the same signed expert map.
