# M8.5.3.3 — Current Hugging Face CDN bridge URL profiles

Live CAS reconstruction showed that current Hugging Face may return signed xorb
fetch URLs on CDN endpoints in addition to `transfer.xethub.hf.co`. Current HF
download documentation explicitly lists `us.aws.cdn.hf.co` and
`us.gcp.cdn.hf.co` as download CDN hosts.

Jend does **not** add a wildcard. Signed reconstruction URLs are accepted only
under two exact profiles:

1. `transfer.xethub.hf.co` / `transfer.xethub-eu.hf.co` with exact
   `/xorb[s]/default/<expected-xorb-hash>` and non-empty
   `X-Xet-Signed-Range`.
2. `us.aws.cdn.hf.co` / `us.gcp.cdn.hf.co` with exact
   `/xet-bridge-us/<opaque-id>/<expected-xorb-hash>` and non-empty
   CloudFront signature fields `Expires`, `Policy`, `Signature`, `Key-Pair-Id`.

The opaque bridge id is syntax-bounded and the final hash must equal the xorb
hash from the reconstruction map. Userinfo, ports, fragments, foreign hosts and
foreign hashes fail closed.

This milestone still does not execute signed URLs. It only validates live
reconstruction metadata.
