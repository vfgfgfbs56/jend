# M8.1 — Durable Weight Page Store

M8.0 virtualized RAM residency. M8.1 makes weight pages durable on local storage
so the page cache survives process/application restarts.

## Content-addressed object layout

Each immutable object is addressed by the SHA-256 of its plaintext page bytes:

```text
weight-store/
  objects/
    ab/
      abcdef...64-hex.page
  staging/
```

The digest is the identity. Two models/releases that reference identical page
bytes use the same disk object.

## Crash-safe publication

A new page is:

1. written to a unique private staging file;
2. created with `0600` on Unix;
3. fully written;
4. `sync_all`ed;
5. re-read and verified by length + SHA-256;
6. atomically renamed to its final content-addressed object path;
7. parent directory synced on Unix.

WeightVM never reads the staging directory. If a process crashes before rename,
the partial file is invisible to WeightVM and is deleted during store recovery.

## Restart semantics

Reopening `DurableWeightPageStore`:

- validates/creates private directories;
- removes stale partial staging files;
- leaves final immutable objects intact;
- implements `WeightPageSource` directly for WeightVM.

No mutable database index is required for object identity in v1: the digest path
is the authoritative index. Future virtual-model mappings will reference these
page IDs separately.

## Integrity

Every read hashes the final object again. A matching filename is not enough.
Tampering/corruption produces `WeightPageDigestMismatch`.

On Unix, an already-existing public (`0755`) store root is rejected instead of
silently treating licensed model weights as public files.

This does not claim protection against arbitrary malware running as the same OS
user; it is a fail-closed local storage boundary against accidents, corruption,
unsafe permissions and incomplete writes.

## Network boundary

The durable store has no downloader and `jend-model-store` still has no HTTP
runtime dependency. Authorized network/model-ingest code may populate objects in
the future, but WeightVM itself consumes only local verified content.

## Next

M8.2 should introduce the virtual model address map:

```text
(model, logical range / expert)
          ->
ordered WeightPageId list
```

with signed mapping metadata and prefetch hints. That is the layer needed before
a router can request "coding expert 17" instead of manually requesting pages.
