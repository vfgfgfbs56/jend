# M7.6 — Dynamic runtime policy application

M7.6 connects adaptive policy to the live scheduler.

`RuntimeScheduler` queue limits can now change at runtime under the same queue
mutex. Tightening a limit never deletes already accepted work. If an AI queue
contains four accepted tasks and its new capacity becomes one, all four drain
normally while new AI submissions receive immediate backpressure until the
depth falls below one.

`RuntimeGovernor` combines `RuntimeController` and `RuntimeScheduler`:

- UI/Vault/Sync queue capacities are preserved;
- `ai_queue_limit` is applied directly to the live AI lane;
- background admission becomes zero when policy disables background workers;
- execution limits expose AI/background worker counts, AI compute share, and UI
  refresh target for future executors/render orchestration.

The worker-count fields are not falsely presented as preempting a currently
running model kernel. M7.6 applies real queue admission immediately; the next AI
executor milestone will consume the execution limits at safe task boundaries.

The deterministic governor smoke simulates a mobile device entering Low Power
Mode, proves new AI/background work is backpressured, proves interactive queue
capacities are unchanged, and proves already accepted AI work is not dropped.
