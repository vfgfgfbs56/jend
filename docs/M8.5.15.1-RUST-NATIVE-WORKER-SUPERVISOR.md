# M8.5.15.1 — Rust-supervised native C++ GGUF worker IPC (offline)

Status: **model-free development protocol proof**, NOT a production sandbox
and NOT a demonstration of model inference.

## Motivation

The user ran M8.5.15 on macOS and confirmed all five C++ protocol-only
worker PASS statements. Jend's goal is to run many already available model
families through a safe common interface. Building a new model or a new
programming language is not required.

Jend may use:
- Rust for trust, cryptography, signed artifacts, orchestration, consent,
  limits, parser state machines and device policy.
- C and C++ for reviewed high-performance model engines and kernels.
- Objective-C / Objective-C++ for isolated Apple system/Metal interoperability,
  NOT for release trust or arbitrary model scripts.
- Architecture-specific assembly or intrinsics after repeatable profiling and
  differential numerical tests against a reference.
- A compact declarative model compatibility/compute descriptor later, but not
  a Turing-complete downloaded script.

## Implemented

client/jend-cli/src/native_gguf_ipc.rs introduces two offline-only components:

1. A pure Rust binary parser validating exact JENDGGUF1 magic, bounded T
   token pieces (<=1024 bytes; <=16 total), terminal D or N, rejection of
   unknown codes, truncated frames, duplicate terminals, N+T mixing,
   nonempty D and trailing output. Each T is raw bytes, not assumed to be
   standalone UTF-8.
2. run_protocol_only_worker: a **dev-only** child process supervisor.
   Starts a caller-supplied absolute regular executable with the fixed
   --protocol-smoke argument, an empty inherited environment, 4096-byte
   prompt cap, 32-KiB stdout cap, suppressed stderr, a 50-ms–5-s deadline
   and kill+reap on failure. It never uses --infer-dev, never gets a model
   path, and never publishes to WeightVM.

The C++ worker now requires EOF immediately after its declared prompt body,
rejecting ambiguous second frames and trailing bytes.

The offline script compiles the C++ worker in protocol-only mode, tests
trailing-data refusal, runs Rust unit tests for malformed frames, then uses
the Rust supervisor against the native executable.

## Release blockers — read carefully

- Test worker path comes from the local smoke script, NOT from a trusted
  binary signature. Rejecting final-component symlinks does not stop
  path races or authenticate the executable.
- Empty environment, stderr null redirection, child process and timeouts
  are **NOT a macOS/Linux/Windows process sandbox**. Malicious native code
  can still use system APIs or spawn children. A pipe reader could remain
  blocked if child descendants inherited its stdout. Do NOT process real
  private conversations or untrusted model-supplied programs with this
  development helper.
- No production OS CPU/RAM/fd/network restrictions, process-group
  termination, binary attestation, signed full GGUF variant, tokenizer
  provenance, real model token generation, or model architecture safety
  checks are demonstrated.
- Before production use, independently pin and attest worker binaries,
  strictly sandbox descendants, verify licensed immutable GGUF weights and
  tokenizer/config signatures, supply read-only capabilities derived from
  the existing M8.5.13 signed-page gate and add fuzzing and real resource
  benchmarks. A checksum obtained from the same untrusted source alone is
  not a publisher trust anchor.
