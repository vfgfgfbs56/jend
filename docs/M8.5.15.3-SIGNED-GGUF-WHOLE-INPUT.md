# M8.5.15.3 — Independently signed complete GGUF inspection

Status: **offline header + byte integrity inspection**, not a real model
runner, native engine authorization, stable snapshot, or sandbox.

## Motivation

User verified M8.5.15.2's seven protocol-only PASS lines on Apple Silicon.
The new universal Jend model interface needs to distinguish an arbitrary
downloaded .gguf from a Jend-authorized, known immutable model variant
BEFORE a native C/C++ backend is even considered.

The repository already has release Ed25519 signatures over canonical
SignedModelManifest, manifest whole-model SHA256, ordered chunks and chunk
SHA256, ChunkVerifier and WholeModelVerifier. This milestone **reuses**
those primitives. A model source, an uploaded file or a checksum stored
alongside the model is never permitted to choose the trusted public key.

## Implementation

crates/jend-model-store/src/signed_gguf.rs

inspect_independently_signed_gguf(key, signed_manifest, absolute_local_path,
max_allowed_file_bytes) requires:
- Separately enrolled trusted ModelReleasePublicKey, verified FIRST, before
  opening the untrusted source path.
- Canonical signed format must be exact "gguf"; nonzero runtime and manifest
  length, with caller limit no more than 16 GiB.
- Existing strictly ordered signed ModelManifest chunks and matching lengths.
- A regular non-symlink path (last component), opened read-only. Stat checks
  before/after streaming; a race-free immutable object is NOT yet offered.
- A 24-byte GGUF v3 little-endian header, nonzero bounded tensor count and
  bounded metadata field count. This is only a prefix validation; it is NOT
  a full GGUF parser, tokenizer audit or architecture compatibility proof.
- Fixed 64 KiB read buffer, per-chunk SHA256 and exact lengths, plus entire
  file SHA256 and length, and refusal of trailing or truncated bytes.
- Return only VerifiedGgufInspection (release identity, length, header facts)
  without a path/executable/native access capability.

**This result cannot authorize execution.** Another process can modify
the file after verification, and a last-component symlink preflight is
not race-free. Production must create an immutable verified CAS snapshot
with an OS-specific stable read-only handle (no attacker-writable backing)
and bind that snapshot to the attested native worker. A user-supplied path
or arbitrary caller-supplied key must never become native worker authority.

Model bytes, keys and signed grants never leave the user's device during
this test. No model/provider API or Hugging Face token is needed.

## Mac offline smoke

    bash scripts/dev-signed-gguf-intake-smoke.sh

Expected:
    Jend independently signed GGUF whole-file inspection: PASS
    Jend GGUF wrong release key and signed manifest refused: PASS
    Jend GGUF corrupt and truncated file refused: PASS
    Jend GGUF malformed header refused even when signed: PASS
    Jend GGUF bounded streaming verification budget: PASS
    Jend GGUF intake fixture grants no native execution: PASS

The tests generate ephemeral Ed25519 keys and tiny bytes starting with a
GGUF-shaped header. **They are synthetic fixtures, not a publisher-signed
real runnable GGUF or proof of neural inference.** Never take their local
test keys and treat them as a production publisher's trust root.

## Remaining product release blockers

- Provision signed publisher/Jend-distributor trust roots independently,
  update and revocation/rollback handling.
- Verify correct exact architecture, quantization, tokenizer and tensor
  layout in a bounded native format scanner before any model load.
- Immutable snapshot protected against time-of-check/time-of-use attacks;
  same digest must be verified as the bytes handed to the worker.
- Attest/pin worker binary, isolate native code by host OS, enforce
  CPU/RAM/threads/disk/time/network limits and prevent automatic remote API
  fallback; mobile needs its own app-signed native integration.
- Use a licensed, independently hashed small actual third-party model
  to test real CPU generation and measure performance on x64 and ARM64.
