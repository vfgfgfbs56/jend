# M8.5.3.1 — Live Xet transfer-path compatibility fix

The first M8.5.3 live CAS run failed closed with `ForbiddenEndpoint`.
Investigation found that current xet-core traffic uses signed transfer paths of
the form `/xorbs/default/<hash>` (plural), while our validator only accepted
`/xorb/default/<hash>` (singular).

This patch accepts only the two exact HF-owned compatibility forms, on the
existing US/EU transfer host allowlist, with the expected 64-hex xorb hash
still embedded in the path and `X-Xet-Signed-Range` still required. It does
not widen to arbitrary hosts or arbitrary paths.

The live smoke now wraps token and reconstruction parser failures with a safe
stage label. Tokens, signed URLs, query signatures, and response bodies remain
unlogged.
