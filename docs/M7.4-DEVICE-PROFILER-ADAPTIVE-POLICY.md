# M7.4 — Device profiler and adaptive performance policy

M7.4 turns the runtime scheduler into a device-aware policy layer.

The profiler uses only coarse local signals: Rust `available_parallelism()` and
RAM capacity (`sysctl -n hw.memsize` on macOS; `/proc/meminfo` on Linux). CPU
model/brand strings are deliberately not read or used, and no profile data is
sent to the server.

Devices are classified as `Low`, `Balanced`, `High`, or `Ultra`. If RAM cannot
be detected, Jend never assumes a tier above `Balanced`.

At saturated runtime pressure the policy protects interaction first: foreground
AI is reduced to one worker, background work/prefetch is disabled, AI queue
depth is reduced to one, animation detail is reduced, and the future GUI target
is capped at 60 Hz.

This does not make model inference itself instant. It prevents model inference
and maintenance queues from making message sending, Vault work, or animations
feel slow.

Test after the normal first-test ladder:

```sh
bash scripts/dev-runtime-smoke.sh
bash scripts/dev-performance-smoke.sh
bash scripts/dev-vault-ipc-smoke.sh
```

The performance smoke must end with:

```text
Jend adaptive performance smoke: PASS
```
