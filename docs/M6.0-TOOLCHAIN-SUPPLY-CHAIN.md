# M6.0 — Current stable toolchain and dependency policy

The headless first-run target now uses Rust **1.99.0**, released 2026-10-01.
The workspace `rust-version` is 1.99 and `rust-toolchain.toml` pins 1.99.0.
CI reads that file instead of duplicating a hard-coded toolchain version.

Why this changed: Rust 1.85 was the initial 2025 baseline. For the first actual
2026 bring-up, keeping an unnecessarily old compiler increases dependency
resolution risk and provides no product benefit yet. A lower MSRV can be
reintroduced deliberately after the service has a green build/test baseline.

`scripts/dependency-policy.py` now rejects:
- git dependencies;
- custom registries;
- path dependencies escaping the workspace;
- wildcard/unbounded registry dependencies;
- registry crates or requirement strings not in the reviewed allowlist.

The first networked Cargo run explicitly performs `cargo generate-lockfile`,
then all metadata/check/test/smoke commands use that lockfile. CI also stores
`Cargo.lock`, `resolved-metadata.json`, and `resolved-tree.txt` as diagnostics.

This is a supply-chain *gate*, not a substitute for auditing dependency source
or vulnerabilities. `cargo check` and the PostgreSQL smoke are still required
before the headless service is considered runnable.


## Clarification added in M6.1

The dependency policy above is an allowlist of direct requirement strings, not
a complete freeze. Compatible semver releases and transitive crates are fixed
only once the first real Cargo run generates `Cargo.lock`.
