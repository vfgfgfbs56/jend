# M6.4 — First test ladder

M6.4 freezes product scope and adds the shortest useful path to the first real
Rust execution.

## Stage 1 — no PostgreSQL or Docker

Run:

```bash
bash scripts/first-test-ladder.sh
```

The ladder performs, in order:

1. static repository/security preflight;
2. dependency policy + source manifest verification;
3. lockfile generation when this is the first Cargo run;
4. a real in-memory OPAQUE registration/login roundtrip;
5. wrong-password rejection;
6. unknown-user OPAQUE fake-record path rejection;
7. JREQ unit tests;
8. gateway DB-independent security/startup unit tests;
9. whole-workspace `cargo check --all-targets`.

This ordering intentionally gives a narrow compiler error before attempting the
entire workspace.

## Stage 2 — PostgreSQL integration

Only after Stage 1 is green:

```bash
JEND_DEV_CLEANUP=1 bash scripts/dev-headless-smoke.sh
```

That path exercises migrations, key generation, gateway startup, OPAQUE HTTP
registration/login, device genesis/binding, JREQ proof-of-possession, replay
rejection, capability refresh, and trusted-device session bootstrap.

## Verification boundary

The ChatGPT execution environment used to prepare this archive still has no
Rust toolchain/PostgreSQL runtime. The new OPAQUE test is source-level ready but
has not been executed here. A green `first-test-ladder.sh` on a Rust machine is
the next acceptance gate.
