# M7.5 — Mobile-aware runtime controller

M7.5 makes iOS/Android first-class runtime targets rather than future ports.

## Platform class

`DeviceProfile` now carries `PlatformClass::{Desktop, Mobile}`. iOS and Android
are classified as Mobile at compile time. Mobile hardware is not treated like a
desktop merely because it exposes many CPU cores or a large amount of RAM.

The mobile baseline caps foreground AI workers at 2, background workers at 1,
AI queue depth at 4, disables background prefetch, and caps the UI target at
60 Hz until the native UI bridge explicitly reports a higher-refresh display.

## Android

Android can read the same coarse `/proc/meminfo` RAM signal used on Linux. No
device model or CPU brand is collected.

## iOS

M7.5 deliberately does not spawn system utilities from an iOS app. Until the
native iOS bridge is implemented, RAM capacity is treated as unknown and tiering
therefore remains conservative. Later Swift/ObjC platform glue can feed memory,
thermal state, low-power mode and display refresh into the Rust controller
without moving secrets out of the Vault.

## Live runtime controller

`RuntimeController` recomputes policy whenever one of these changes:

- scheduler pressure;
- thermal pressure (`Nominal`, `Elevated`, `Critical`);
- power mode (`Normal`, `LowPower`).

On mobile low-power or critical thermal state, AI is reduced to one worker,
background work is stopped, prefetch is disabled and queue depth is minimized.
The purpose is sustained responsiveness and battery/thermal safety, not maximum
short-lived benchmark throughput.

The performance smoke simulates a high-end mobile device even on macOS, so CI
can continuously enforce the mobile policy before dedicated iOS/Android runners
are added.
