# M8.5.15 — Pinned native GGUF CPU worker experiment (protocol proof)

Status: **development-only prototype, NOT secure production inference**.

The user has confirmed six PASS on M8.5.14 on macOS. Jend's product
direction is universal, third-party local models, not a Jend-created model.
This milestone begins the real C++ CPU engine boundary while leaving
the signed Jend WeightPage and Rust E2EE/network security intact.

## What actually exists

- `native/jend-gguf-worker/worker.cpp`: standalone C++17 binary. It parses a
  bounded length-prefixed prompt on stdin, not argv; stdout has strictly
  versioned binary frames. It exposes a compile-time protocol-only mode
  (no model or llama.cpp dependency, used in GitHub CI).
- Optional `JEND_WITH_LLAMA` dev build links llama.cpp's real C API for
  tokenization, greedy CPU-only generation and streamed byte-token frames.
  No GPU, no network client, no downloaded scripts, no Python
  trust_remote_code. Strictly <=4096 bytes prompt, <=512 context tokens,
  <=16 generated tokens, <=4 GiB dev model file. A compiled native worker is
  disabled unless the explicit environment variable
  `JEND_ENABLE_UNSANDBOXED_NATIVE_DEV_EXPERIMENT=1` is set.
- `CMakeLists.txt` refuses any llama.cpp checkout except the exact pinned
  commit `45451c366d4256f94fbc8845645e31a6b9155054`. The dependency
  is **not downloaded automatically by Jend**. CMake builds CPU-only with
  CUDA/Metal/Vulkan off.
- `scripts/dev-native-gguf-worker-protocol-smoke.sh` compiles and executes
  the C++ protocol-only worker with malformed, oversized, truncated and
  unsupported-argument inputs. It can never load model weights.

## Protocol v1

Client writes exactly 4-byte unsigned big-endian prompt length followed by
up to 4096 prompt bytes. Process is one-shot. Worker stdout:

    JENDGGUF1                  (9 fixed ASCII bytes)
    T [u32 BE length] [UTF-8/piece bytes]  (native only)
    D [u32 BE zero]            (successful native completion)
    N [u32 BE eight] NO_MODEL  (protocol-only fixture)

Frame length max 16 KiB. Unknown frames, truncated payload, extra frames and
arbitrary noncompliant worker binaries must be rejected by the future Rust
orchestrator. No secret keys, signed URLs, prompt bytes or token data are
logged to stderr by this Jend shim. Upstream llama.cpp itself may emit other
diagnostics, so production log capture must be centrally redacted and disabled
by default.

Cancellation: parent terminates worker process. Crash containment, sandbox
permissions and memory/time quotas **are not yet implemented**.

## Experimental native backend build (explicit opt-in, NOT user-facing)

Users who independently have a licensed GGUF artifact and want to conduct
local unsafe DEVELOPMENT experiments may separately clone the pinned
llama.cpp commit and compile:

```bash
git clone https://github.com/ggml-org/llama.cpp.git /tmp/jend-pinned-llama
git -C /tmp/jend-pinned-llama checkout --detach 45451c366d4256f94fbc8845645e31a6b9155054
cmake -S native/jend-gguf-worker -B /tmp/jend-native-cpu-build \
  -DJEND_BUILD_EXPERIMENTAL_LLAMA=ON \
  -DJEND_LLAMA_SOURCE=/tmp/jend-pinned-llama
cmake --build /tmp/jend-native-cpu-build --target jend-gguf-cpu-worker -j2
```

The executable needs a strict stdin frame and explicit
`JEND_ENABLE_UNSANDBOXED_NATIVE_DEV_EXPERIMENT=1`, then
`--infer-dev --model /absolute/path/to/local.gguf`. **Do not** use the
experiment with private conversations or unknown GGUF files. This is not a
validated production launcher. The user can first verify build/CLI capability
without supplying any weights.

## Production release blockers

1. Verify a complete GGUF variant and tokenizer/config digests against an
   independently provisioned trusted signing key, with immutable materialized
   read-only file handle/capability; never let an upstream model supply the
   expected digest. M8.5.13 proof is currently on tiny synthetic Xet pages,
   not complete GGUF variant bytes.
2. Rust parent must spawn ONLY a reviewed/pinned native worker binary with
   artifact signature attestation; a model may not choose executable path
   or execute supplied code.
3. Enforce OS sandbox blocking outbound/inbound networking, arbitrary
   filesystem, chat database/vault access, helper processes, dylib loading and
   dangerous syscalls, with CPU/RAM/time limits, protocol response parser and
   bounded cancellation.
4. Fuzz GGUF parsing and protocol; use native ASan/UBSan tests where
   supported; reject unsupported model architectures/quantization before
   backend invocation. Pin and monitor upstream CVEs and ABI.
5. Build integration tests with a trusted/licensed tiny GGUF fixture and
   compare generated token outputs across platforms and runtime versions.
   CI **does not** fetch third-party model weights.
6. Profile RAM, first-token latency, tokens/s and energy on Mac and weak CPUs,
   enforce `runtime_feasibility` before launch; no invisible API fallback.

CI passing this branch means ONLY standalone C++ worker protocol validation.
It does not mean a real third-party GGUF was executed, sandboxed or admitted
through WeightVM. These are next implementation milestones.
