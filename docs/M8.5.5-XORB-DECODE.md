# M8.5.5 — Bounded Xorb Decode + Logical Probe Reconstruction

M8.5.5 decodes the single authorized physical xorb range proven in M8.5.4.
It implements the published Xet v0 8-byte chunk header and the current three
compression schemes: None, LZ4 frame, and ByteGrouping4+LZ4 frame.

Security boundaries:

- raw chunk output is capped at 128 KiB per the Xet format;
- exact reconstruction chunk count is taken from authenticated CAS metadata;
- every chunk payload must fit the fetched body exactly;
- LZ4 output must equal the header's declared uncompressed length;
- total decoded output has an explicit caller budget;
- trailing bytes, unknown versions/schemes, truncated records and mismatched
  term unpacked lengths fail closed;
- live smoke still supports only one fetch / one physical range and decodes at
  most 16 MiB;
- decoded logical bytes remain outside WeightVM because this smoke does not yet
  carry a signed Jend `expected_page` SHA-256.

The CLI Source Worker gains one direct dependency: `lz4_flex = =0.13.1`, matching
the current 0.13 line used by xet-core and including the checked-decode security
fixes. `jend-model-store` remains free of network and LZ4 dependencies.

Because this milestone adds one dependency, copy the previously verified M8.5.4
`Cargo.lock`, then run `scripts/prepare-m8.5.5-lock.sh` once. That performs one
non-locked `cargo check` only to extend the existing lock with the pinned LZ4
decoder and its dependency, rather than regenerating every locked transitive
version. All subsequent test-ladder commands remain `--locked`.
